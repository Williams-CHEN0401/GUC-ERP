## 報表與重新讀取

- ERP 與會計的工作內容統計固定列出 `projects.project_type = construction`；其他工作內容仍保存在原系統。
- 使用既有 `work_content_report_v1`，讓選項、明細及「全部」匯出採同一限制；直接傳其他分類也會被後端拒絕。
- 原有工程施工工作內容的用料、退料、工資、相關日誌、進度及權限計算保持一致。人員數量與施工投入的算式不變，顯示單位改為「天」；代工依每日最高人數累計施工投入天數。
- 重新讀取卡住的原因是載入畫面覆蓋報表後，前次 HTML 快取標記仍存在。回傳資料相同時略過重畫，永久停在載入畫面。現已在顯示載入／空資料／錯誤狀態時清除該標記，並讓不完整回應明確顯示錯誤。
- 保留請求世代檢查，避免較舊回應覆蓋新的篩選或刷新結果。

新增 migration：`supabase/migrations/20261021022638_construction_only_work_reports.sql`。只在 `guc_dashboard_preview_20261012` 套用與驗證。它取代同一既有函式，沒有新增資料表、Auth、主資料或權限模型；函式 ACL 維持原值。將來正式發布須將此 migration 與受影響的 Gateway／網站版本一起發布。

## Excel 上傳

- 報價單 `.xls`／`.xlsx` 上限為 **15,000,000 bytes（15 MB）**。
- 前端選檔檢查、伺服器 multipart 檢查、兩種 Excel 解析器及測試代理一致。
- 15 MB 整數邊界可解析；多 1 byte 拒絕；multipart 額外預留 20,000 bytes。
- 目前 Docker Caddy 直接代理 Next.js，沒有另設較小 request body 上限；此路徑不是 Server Action。
- 原有 ZIP／XML 檢查、巨集與外部連結拒絕、解壓大小與明細筆數限制保持原樣。檔案符合容量仍須通過格式、客戶及資料驗證。
- 此次驗證的是本機 Docker 對應的 Next.js／HTTP 路徑；未發布或變更 Vercel 平台的請求大小限制。
