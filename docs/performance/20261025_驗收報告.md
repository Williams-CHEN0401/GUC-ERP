# GUC ERP 績效模組驗收報告

日期：2026-10-25（Asia/Taipei）。狀態：**CSV 24／24 項自動驗收通過**。這是隔離測試結果，未宣稱正式站或手機實機已完成驗收。

## 執行環境與證據

測試專案 `guc-performance-test` 使用真實 Supabase Auth、ERP API 代理、Edge Runtime Gateway、PostgREST 與 PostgreSQL 17.6。後端案例走 HTTP 請求、資料庫保存與重讀；瀏覽器案例走實際登入及 UI 操作，不以 mock API 代替。採 schema-only 基準與合成資料，正式業務資料寫入為零。

資料網路為 internal，專用資料卷與測試金鑰；只有 ERP 透過 `127.0.0.1:4268` 提供預覽。無正式 volume、NAS 目的地或正式登入憑證。詳見 [隔離檢查](evidence/isolation-results.json)。

證據代碼：D＝[資料庫／Gateway](evidence/database-results.json)，B＝[三瀏覽器流程](evidence/browser-results.json)，O＝[功能關閉回歸](evidence/feature-off-results.json)。原始要求見 [CSV](sources/acceptance-v1.csv)。

## 發現與修正

- 延伸舊指派測試 fixture，補齊正式已部署施工監控要求的四個可空關聯欄位；未修改既有指派規則。
- 修正權重 JSON 在 Docker 靜態路由遭拒問題，只放行指定檔名，保留其他 JSON 的拒絕規則。
- 來源詳情加上每次授權檢查，來源刪除後封存摘要遮蔽；指定主管建立公共任務限制於管轄員工與月份。
- 切換登入帳號清除績效快取；設定驗證失敗保留使用者輸入。
