# 評核收合與項目版本調整

基準：GitHub main `e4ca6bdfdffbdf379f141a43c4e555bf59d9eb99`，正式 PostgreSQL 17.6。

## 已確認需求

- 評核明細改為施工規劃明細相同樣式的收合清單，預設收起，摘要顯示職務、項目及目前評級。
- 保持原有七項代碼，管理員可修改名稱、說明及四種職務的權重。「現場帶班／主管」更名為「主管職務」，只有此職務可新增考核子項目；其他三職務仍維持原本七項。
- 修改建立新的不可覆寫版本；新月份可選新版，指定草稿可個別套用，已送出／核定／發布內容保持原版。

## 資料與功能變更

- `performance_reviews` 增加可空的 `template_id` 外鍵及索引；空值沿用月份版本，不回填既有評核。
- 擴充既有 `performance_command_v1` 的草稿換版操作；沿用管理員權限、列鎖、row_version、request_id 與 audit_logs。
- 新版建立與草稿套用同一交易完成，避免衝突時留下半成品。也可選擇既有版本套用。
- 草稿換版需填原因，明確確認清除舊評級後重新評分；保留職務配比、佐證與改善行動。後端重新計算，操作前後資料及版本可稽核。
- 評核讀取、計分及新修訂皆使用單筆評核的有效版本；既有月份及已發布評核不被重寫。
- 新增主管子項目存於原設定 JSON 的 lead.additional_criteria，沿用 performance_role_weights 與 review_items；新代碼不影響其他職務。主管全部項目權重合計仍須 100%，計分由後端依此版本計算。
- 前端依版本設定顯示名稱、說明及權重，取消硬編碼名稱作為主要顯示來源。收合不清除尚未保存的欄位內容。
- 不改 Auth、Gateway 路由、權限授予或其他 ERP 模組。

## 驗證與發布

先在隔離環境套用單一增量 migration，驗證七項名稱／說明／權重保存重讀、草稿單獨套用、其他評核不變、非法權重／角色／過期版本拒絕、冪等重送與稽核、送出後鎖定、發布後新修訂繼承版本，以及既有 24 項驗收。

瀏覽器實測預設收合、逐項展開編輯、收合後保留輸入、保存後重讀、錯誤時保留輸入、模板編輯與套用，以及 390px／1440px 版面；執行既有 `npm run check`。

正式發布前確認來源及資料庫函式基準、備份及相容性；只套用本次 migration 並更新 ERP 容器。Gateway 不需更新。保留舊映像與來源，資料庫欄位與新版設定保留，禁止用刪除業務資料回復。
