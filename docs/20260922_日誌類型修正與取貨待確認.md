## 已修正：每日工作類型獨立保存

根因：日誌 trigger 把 work_type 寫回 projects.project_type，再同步到全部同工作日誌；project writer 另有一段批次覆寫 work_type。

新行為：

- 建立全新工作內容時，仍由既有建立函式以第一篇日誌類型初始化主檔類型。
- 後續新增、修改日誌只保存當篇類型，不覆寫主檔及其他日誌的類型。
- 修改主檔類型也不再抹除每日實際工作類型。
- 保留共用名稱／狀態同步、原編號、科室、施工人員、維修明細、Auth、RBAC、RPC 簽章及原 ACL。
- 前端 session preview 配合同樣規則，正式日誌表單不改版。

必要 migration：supabase/migrations/20260922103001_preserve_daily_work_log_type.sql。
此檔僅替換三個既有函式，沒有回填、刪除或重建資料；尚未套用正式 DB。
過去已被覆寫的日誌類型不會憑空還原；本次未修改歷史資料。

## 取貨：已定位，尚未修改

UI 的 update_pickup → inventory-gateway → update_pickup_record 在已關聯日誌且目標工作不同時主動拒絕，錯誤與截圖相同。
目前只是刪掉 guard 會留下「取貨指向 B、日誌仍指向 A」的不一致，不能直接移除。

已向使用者詢問兩種業務結果：

1. 建議：只更正此筆取貨，解除不相符的原日誌連結，原日誌及其他取貨保留。
