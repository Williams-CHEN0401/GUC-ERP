# 兩類線材單據自由登錄

日期：2026-11-12（Asia/Taipei）。GitHub main 查核基準：`956bdfff8e2254dbdc1df5576c74594525572340`。開發分支：`codex/cable-stock-flexibility-1112`。

使用者確認：兩類線材庫存或餘料不足時，允許先登錄、保留負庫存，之後人工盤點校正。

本次僅修改「弱電線材」「電線&電纜類」（含全形 & 名稱）的數量可用性限制：

- 取貨不再要求必須先有餘料、必須選餘料箱、先設定包裝長度，或必須有足夠整包庫存。
- 有選餘料箱時，仍保留該箱的來源與個別扣減；可扣成負數，零米／負數箱仍可選取，不合併或挪用其他箱。
- 已知長度時只拆用實際可用的整包，差額列負米數，不虛增整箱或進貨。例如 2 箱各 100 米領用 250 米，只拆 2 箱，米數帳面為 -50。
- 進貨、公司到貨確認、進貨更正／刪除與案場餘料入庫，可以在米數帳面仍負數時完成。0 米取 12 米為 -12；再進貨 5 米為 -7；之後可人工校正。

保留數量為正、米數最多兩位小數、有效單位、客戶工作關聯、餘料箱屬於同一品項、版本衝突、重試防重複、整批原子性、RBAC、RLS、稽核及其他貨品的原有規則。供應商退貨的既有庫存規則未納入本次修改。既有日期、價格、科室、品項名稱及計價流程未變更。

## 實作

`app.js` 沿用既有分類判斷，僅調整餘料來源是否必選及零／負數箱的選項；版面與操作位置保留。

新增 migration `20261112101833_cable_stock_flexible_documents.sql`，新增一個分類商業規則 helper，調整五個既有數量觸發函式與既有庫存調整 constraint。沿用原函式 OID、擁有者、ACL、search_path 與 invoker 模式；新 helper 僅 service_role 可執行，不增加公開 Data API 權限，也不建立新的 Auth、商品、客戶或庫存資料模型。

保留既有 site_return 與 remnant_count_scope 的 constraint 例外，沒有回填或重寫任何歷史資料。只有本次新 migration 需在正式發布時套用，未修改已套用的歷史 migration。
