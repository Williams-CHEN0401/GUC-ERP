## 修改與邊界

- ERP `20261004152032_erp_private_data_access.sql`（尚未發布）：關聯範圍延伸至報價及案場匯入／版本；多工作報價只要一個關聯工作受限，整份報價受限；歷史 Audit 及已封存私人日誌仍受保護。equipment_registry 的多型 source_id 也追蹤。scope RPC 使用固定空 search_path、service-only SECURITY DEFINER，不額外開放原始報價資料表。
- 新 ERP `20261005005222_cross_system_private_access.sql`：每個交易以後端驗證的 actor 準備 scope；security_invoker 檢視表在搜尋、count、分頁、設備彙總前過濾；四個設備／工作範圍讀取 RPC 加可信任 actor 包裝，禁止以另一人的 p_user_id 代入。
- inventory-gateway：三個設備 RPC 及 work_log_scope 呼叫保護版 RPC；URL 每個值與 payload 的 UUID 都檢查（包含大寫、文字內嵌與重複參數）。沿用既有寫入、角色、備份回復防護及 response 最後一道檢查。
- 新 inventory-gateway-preview-optimization 入口只匯入同一 handler；仍依既有 Preview 規則禁止寫入，避免部署不同版本漏掉防護。
- 新報價 `20261005005228_quotation_private_access.sql`：明列唯讀 RPC 的 FROM／JOIN 改用受限檢視表；既有 service-exposed 報價 RPC 包裝前後存取檢查，內部原函式撤銷 client／service 直接執行權限；保留既有簽章、版本鎖、DML、金額規則與回傳形狀。輸出檢查失敗使整個 SQL 呼叫回滾。
- quotation-gateway 僅將私人「權限」錯誤正確回傳 403。Excel 匯出原有的資料讀取入口經同一 SQL 防護，不更改 Excel 版型。
- 一般 admin 不能自動查看私人資料；核准「單筆日誌唯讀」不代表核准報價、客戶或案場設備。啟用前／正式授權名單的既有行為保留。
- 兩站 UI 檔案沒有修改；沒有執行正式批次分類、帳號變更、資料刪除或 NAS 寫入。

## 待授權發布時的必要順序

1. 唯讀核對正式 schema／FK、四個既有設備／工作範圍 RPC、報價多工作／保固 migration、帳號對應及舊日誌最早建立者 Audit 覆蓋率；保存可回復點。確認所有正式／Preview backend 別名，不能留漏用舊 handler 的入口。
2. 在 staging／隔離正式規模資料測試每請求 scope 計算時間、REST URL 長度、並行撤權及多連線；這些本輪未驗證，不以小型 PGlite 結果代替。
3. 依序套 ERP `20261004151329`、`20261004152032`、`20261005005222`，再報價 `20261005005228`。跨 repo migration 不可只執行報價 migration。套用後核對函式、檢視表與 EXECUTE grants。
4. 更新所有共用 inventory-gateway 正式／Preview 入口，以及**最新報價 repo** 的 quotation-gateway／quotation-gateway-preview，再配套前輪 ERP 網站。ERP repo 內舊 quotation-gateway 不得覆蓋最新報價後端。
5. 使用已授權真實帳號驗證三站讀寫、撤權、匯出及既有 NAS 流程。此步及正式四人登入均尚未做。

舊設備 RPC 僅保留 service-only 以支援部署過渡；防護依賴所有入口都更新。新建 RPC、改動原讀取 SQL、增加多型／JSON 關聯後需同步重驗私人範圍，不能假定自動涵蓋。

回復策略：保留資料與原設定，優先向前修正；啟用隱私後，不得回退到不認得 ACL 的舊 Gateway 並聲稱仍安全。如需回退應先停用受影響入口，再明確核准處理；不刪除資料表或私人標記。
