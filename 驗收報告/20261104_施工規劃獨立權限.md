## 問題與修正

原本施工日誌以建立人、工作內容負責人與一般日誌權限決定可見範圍；20261025 的施工監控規則又將子項目完成勾選綁定管理施工規劃。一般施工人員可能只能看自己的歷史日誌，也無法勾選子項目。

沿用 `app_roles`、`role_permissions`、`project_workers`、`construction_plan_assignees`、現有 Auth 與 Gateway/RPC，沒有新增另一套權限或主資料。

系統設定 → 權限管理 → 選擇角色，增加獨立的「施工規劃權限」區塊：

| 設定 | 可控制的操作 |
| --- | --- |
| 施工規劃 | 查看、新增、修改、刪除 |
| 子項目完成勾選 | 查看、修改；修改控制勾選及取消完成 |
| 施工日誌 | 查看及本人日誌新增、修改、刪除 |
| 其他人的施工日誌 | 查看、修改、刪除，須同時具施工日誌對應操作權限 |

未啟用「獨立設定施工規劃權限」的角色維持既有規則；啟用後明確未勾選即拒絕，不會被一般工作內容／日誌權限覆蓋。管理員保有既有完整權限。權限仍受工作內容範圍、指派與私密資料限制，不會因勾選而取得無關工作內容。

若要讓冠霖查看同一規劃中其他人的歷史日誌並勾選完成，管理員可在其角色啟用獨立設定，勾選「施工規劃／查看」、「施工日誌／查看」、「其他人的施工日誌／查看」及「子項目完成勾選／查看、修改」。新增、修改本人日誌可另行勾選；不需要因此授予修改施工規劃或修改／刪除其他人的日誌。若不希望影響同角色其他帳號，可沿用現有角色管理建立適用角色再指派帳號。

前端使用 RPC 回傳的日誌修改／刪除及子項目操作能力；後端與 SQL 重新驗證資源及操作。完成紀錄、原建立人、封存、稽核、版本鎖、規劃與日誌關聯均保留。一般工作日誌在沒有施工規劃權限時仍可開啟。
