## 可觀察結果

- 同一張案場餘料入庫單允許相同品項多列，每列散料獨立保存為一箱，可填箱號／備註；不再提示合併品項或自動加總每段米數。
- 66、189、100 米保存為三筆獨立明細。即時庫存顯示「餘料 3 筆」與各箱米數，未分箱散料另外顯示，不將三箱顯示為合計 355 米。
- 取貨可指定餘料箱；從第二箱取 12 米後，三箱為 66、177、100 米。改單換箱先回沖原箱，再扣新箱；同單可使用同品項不同箱，不可跨箱超領。
- 工作日誌取貨共用相同來源欄位與後端扣庫流程；供應商米數退貨及盤點也保留來源，避免其他流程把分箱庫存當成未分箱散料扣除。
- 餘料入庫使用與取貨單相同的標題、明細卡、序號、按鈕與網站色系，增加客戶編號／名稱搜尋，可先搜尋再選分類與客戶。搜尋品項仍在下方獨立區域。
- 舊的合計散料保留為未分箱資料，不推測箱數或改寫原交易。若使用者主動拆分，可移除舊列並新增各箱實測米數。
- 原先允許未登記取貨入庫、改單／取消後產生負庫存並由人工校正的行為保留；每箱短缺可個別盤點。舊交易與來源紀錄持續保留。

## 資料與權限

本次 migration 為 20261105001137_inventory_remnant_boxes.sql，由已安裝的 Supabase CLI 產生檔名。擴充既有 site_return_lines、pickup_records、supplier_return_lines 與 stock_adjustments；用既有入庫明細作為物理餘料箱，不建立另一套貨品、Auth 或權限資料。

移除入庫單「同品項只能一列」的唯一約束，依明細 ID 保留來源與異動。新增箱號、分箱狀態、列序與扣庫／盤點來源，更新8個既有函式，新增7個 SECURITY INVOKER helper，使用空 search_path，取消 PUBLIC、anon、authenticated 直接執行權，只授予 service_role。既有 RPC 身分、擁有者、ACL、RLS 與安全設定保留。

庫存數學仍由原庫存紀錄計算；分箱餘額由入庫異動、指定箱取貨、供應商退貨與盤點差額推導，不儲存第二份可自行修改的庫存餘額。數量修正、更改品項、取消及刪除保留舊列與不可變庫存異動，不能把曾取用的箱 ID 改指另一種品項。
