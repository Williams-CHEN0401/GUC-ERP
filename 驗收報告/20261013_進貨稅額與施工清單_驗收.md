## 2. 金額及稅額計算

**稅率來源**：原報價 `private_base_quotation_options_v1` 已有 TWD、預設稅率 500 basis points（5%）與四捨五入設定；抽出為 `erp_money_settings_v1`，報價與進貨共同引用。前端由 Gateway 取得設定，不另寫固定 5%。使用者可在單據指定 0–100%、最多兩位小數，保存為整數 basis points。

沿用既有進貨正整數數量及兩位小數單價；TWD 品項小計先四捨五入至整元，再計整單稅額。正數恰好一半時向上，與 PostgreSQL numeric `round` 一致。前端使用 BigInt 十進位計算避免浮點誤差。

- 未稅：各列 `round(數量 × 未稅單價)` 加總＝未稅金額；稅額＝`round(未稅金額 × 稅率)`；含稅總額＝前兩者相加。
- 含稅：各列 `round(數量 × 含稅單價)` 加總＝含稅總額；未稅金額＝`round(含稅總額 ÷ (1 + 稅率))`；稅額＝兩者差額。
- 切換模式只依目前原始輸入重算，不將先前算出的稅額加回輸入。
- 任一列尚無單價，整單總額保持「未設定」。單價 0 有效。歷史計稅模式為 NULL 的單據保留原單價，不推測是否含稅，不生成假稅額。
- 後端 `save_stock_receipt_document_v4` 沿用 v3 庫存、版本與 CRUD 權限驗證；保存後以 ledger 實際資料再計算。即使無價格 VIEW 也執行驗證，回傳則不包含財務摘要。前端傳入的總額不會成為保存來源。

**同步方式**：既有 `stock_transaction_documents` 單頭增加 `receipt_tax_mode`、`receipt_tax_rate_basis_points`、`receipt_project_id`，明細仍在 `stock_receipts`。金額每次查詢從現存明細推導，不另建重複金額表。只有明確關聯 `projects.id` 的單據才進入該專案的「關聯進貨歷史」，按單頭加總一次；新增、修改、刪除後重新讀取即反映。

單據無工作內容 ID 時保持未分配，不能用客戶名稱推測歸屬。舊單若要納入某工程的進貨歷史，需由使用者編輯單據並明確指定「關聯工作內容」。進貨日期套用報表日期區間。

**人工單價**：`accounting_material_prices` 的已保存人工單價優先，包含 0；未設定時才沿用同品項最近進貨參考價。含稅來源轉為兩位小數未稅參考單價，原始輸入仍保留於進貨歷史；未知舊單標明「歷史計稅未設定」。這個既有品項參考價 fallback 不代表將未分配進貨單歸屬至工程。

材料參考金額保留既有「領用數量 × 參考單價」口徑與兩位小數，與「關聯進貨歷史」各自呈現，兩者不相加。修改人工單價不回寫進貨記錄。

**權限**：ERP 進貨價格 VIEW 控制單價及稅額總額；CREATE／UPDATE／DELETE 沿用原獨立價格權限。設定計稅資訊須具 VIEW 及對應 CREATE／UPDATE。會計金額維持原 `accounting_prices` 權限；所有新 RPC 禁止 anon／authenticated 直接執行，只由已驗證身分的 Gateway 呼叫。
