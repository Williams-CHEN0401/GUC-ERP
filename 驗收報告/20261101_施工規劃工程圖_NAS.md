# 施工規劃工程圖與 NAS

狀態：功能完成、隔離測試通過；尚未正式發布或推送 GitHub。

## 使用方式

測試網址：http://localhost:4500/?page=projects

在「工作內容 → 施工規劃」展開規劃，按「工程圖」。客戶與工作內容由規劃固定帶入，選擇該客戶已啟用的承攬內容，只有一種時自動選取。工作內容負責人及具既有管理權限的人員可上傳，具規劃查看權限的人員可查看與下載。

- PDF、JPG/JPEG、PNG、WebP 可開新分頁查看；HEIC/HEIF、DWG/DXF 提供原檔下載。
- 沿用工作日誌附件限制：每檔最多 20 MiB，每次最多 30 檔、合計 600 MiB；逐檔及分段傳送。
- 同名檔案可明確選擇覆蓋、另存或取消；另存後清單顯示實際儲存檔名。
- 已成功的檔案會保留；NAS 成功而索引失敗時，只重試索引保存。
- 傳送 100% 後仍等待 NAS 大小／SHA-256 校驗及索引保存，完成後重新讀取清單。

測試服務使用合成資料、隔離 SQL 與記憶體 NAS；重啟會清除測試資料與檔案。頁面有明確提示。2026-11-01 已分別唯讀檢查實際 NAS 的 `/GUC-ERP` 與使用者指定的 `/施工規劃圖` 共用資料夾，PROPFIND 均回應 HTTP 207。新共用資料夾已存在，沒有建立新共用資料夾、修改 NAS 權限或寫入真實檔案。

## 設計與權限

沿用既有 WebDAV 帳密設定、ERP session、construction_scope_v1／construction_project_access_v1 及 site_assets。新增可空 construction_plan_id 與 contract_service_type_id 外鍵，保存規劃與選定承攬；原附件仍透過原有 site_id 關聯承攬。沒有另一套客戶、帳號、設備或承攬主檔。

新目錄為 `/施工規劃圖/{客戶名稱}/{承攬內容名稱}/{工作內容名稱}/{台北上傳日期}/{施工規劃 UUID}/{檔名}`。前四層沿用工作日誌附件命名，最後以規劃 ID 隔開同一工作內容的多筆規劃。伺服器決定正式路徑，畫面先提示預計位置，上傳時改顯示實際位置。名稱正規化與 NAS 一致，含全形、結尾標點及 Unicode 長度處理。

工作日誌的 `NAS_WEBDAV_ROOT=/GUC-ERP` 維持原值；工程圖由伺服器指定獨立根目錄 `/施工規劃圖`，兩者共用既有 WebDAV 連線設定，不能由瀏覽器任意切換根目錄。既有 `/GUC-ERP/施工規劃/...` 索引可繼續唯讀下載，不移動舊檔、不接受舊根目錄上傳票證。客戶／承攬／工作內容改名後，既有附件沿保存的路徑讀取。

NAS 帳密僅留在伺服器。下載使用附件 ID，經 Gateway 重新驗證權限、路徑、大小及雜湊，不接受客戶端任意 NAS 路徑。已停用或未關聯此客戶的承攬無法上傳，跨承攬／規劃／根目錄票證會被拒絕。

每次上傳／分段／索引保存均驗證當下權限，保留私人客戶限制。登入失效時在解析 multipart 前拒絕；帳號切換會關閉未完成的查看視窗，停止舊流程後續索引保存。若 NAS 已完成寫入而登入同時失效，保留原檔、不擅自刪除，需重新登入核對檔案狀態。

一般附件及舊備份 API 不會繞過施工規劃權限讀取工程圖；既有原生資料庫備份仍可包含新索引。已有工程圖的施工規劃不可刪除，應改為取消以保留歷史關聯。
