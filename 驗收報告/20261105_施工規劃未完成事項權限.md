# 施工規劃日誌未完成事項結清權限

已修正受指派施工人員無法勾選其他填寫人日誌待辦的問題。此變更尚未正式部署、推送 GitHub 或合併 main。

來源為 GitHub `Williams-CHEN0401/GUC-ERP` 的 `fix/remnant-boxes-1105`，基準 `b80df4c54c06739b6c1bb80b22ae2fe56451c732`；遠端 main 為 `9b8d0e5667dba4467cd20f3e95c901058cfc9ac3`。本機修正分支為 `fix/construction-pending-assignees-1105`，保留目前已發布、尚未合併 main 的功能。開始工作與交付前均 fetch 查核來源。

## 問題與修正

原先 `pending_work_log_items_v1` 的 `can_complete`，以及儲存時的 `save_work_log_workforce_before_maintenance_v1`，都要求能 UPDATE 原日誌。即使已被指派到該施工規劃，仍會因不是原日誌作者、沒有修改別人日誌的授權而被停用。

新增私有 `construction_pending_completion_allowed_v1`，沿用 `construction_plan_assignees`、`construction_permission_v1`、既有私有資料判斷及正式儲存鏈。只有啟用帳號、有效施工規劃、目前被指派者，且有施工規劃／施工日誌檢視及施工日誌寫入能力，才獲得結清該規劃未完成文字的能力。一般非施工日誌維持原權限。

列表與儲存共用此判斷；施工專用角色無一般日誌權限時也可讀取已授權的施工待辦，維修待辦入口仍使用原授權。查詢只投影待辦，不新增其他作者整份日誌的檢視／修改／刪除權限。原先明確設定的施工權限拒絕、私有客戶、取消／刪除規劃及跨工作內容限制仍有效。

儲存前鎖定來源規劃以與重新指派序列化，保留原日誌版本、日期、來源工作內容、待辦原文、重複選取及 request replay 檢查。不變更角色權限資料或個別帳號權限，也不變更施工子項目本身的完成勾選設定。

來源日誌的未完成文字仍留原處並加註完成日期，例如 `待辦A(11-05已完成)`；本日日誌已完成欄新增同一文字，雙向歷程保留成立日、結清日及操作人。來源作者、其他已完成內容保持原樣，尚有其他待辦時不提前結案。UI 僅調整無權限提示為「無結清此未完成項目權限」，排版、字體、顏色與操作流程不變。
